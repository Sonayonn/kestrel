@kestrel/sdk

Kestrel SDK

The conditional-order layer for Solana perps, as one import. Arm a private order, read its live state, and stream fills — the SDK wraps the on-chain program, the rollup delegation, and the TEE permission flow.

Overview

A Kestrel order is a condition watched inside a MagicBlock Ephemeral Rollup and sealed in a TEE. You arm it with one signed call; a crank evaluates it every tick; when it fires, a Magic Action writes an on-chain receipt and a keeper settles the position on FlashTrade. The SDK is the client surface over that pipeline — it runs in node (keepers, bots) and the browser (anchor bundles under Vite/webpack).

Installation

shell
npm install @kestrel/sdk @solana/web3.js @coral-xyz/anchor @magicblock-labs/ephemeral-rollups-sdk

You'll also need the program IDL (target/idl/kestrel.json from anchor build) and an Anchor-compatible wallet.

Quickstart

quickstart.ts
import { KestrelClient } from "@kestrel/sdk";
import idl from "./kestrel.json";

const k = new KestrelClient({
  connection, wallet,
  programId: "JXiSmxyKzXaiCQ28WawpQ3RBmCPuw3Gvvfzg4VTKyML",
  idl,
});

// arm a private stop-loss — one call: create + delegate to the TEE
const { id, order } = await k.arm({
  kind: "stop_loss", side: "close",
  triggerPrice: 140, referencePrice: 150,
  size: 11_000_000, private: true,
});

// stream every status change: armed → triggered → settled
const stop = k.watchFills(f => console.log(f.status, f.entryPrice));

KestrelClient

Construct once, reuse for all calls.

constructor
new KestrelClient({
  connection: Connection,   // a Solana connection (devnet)
  wallet: Wallet,           // Anchor-compatible signer
  programId: string,
  idl: Idl,
  routerUrl?: string,       // MagicBlock router (defaults to devnet)
  routerWs?: string,
})

arm(params)

Creates the order on-chain and (by default) delegates it into the Ephemeral Rollup. Returns the order id and PDAs.

FieldTypeNotes
kind"stop_loss" · "take_profit" · "trailing_stop" · "limit_buy"condition type
side"open" · "close"what the fill does to a position
triggerPricenumberthe price the crank watches for
referencePricenumberprice at arm time (sets trailing high-water)
sizenumberposition size, base units
trailOffset?numberoffset for trailing stops
private?booleanseal the order in the TEE
delegate?booleanpush into the ER (default true)
returns
{ id: BN, order: PublicKey, fill: PublicKey, sigs: string[] }

listFills()

Returns every fill receipt — the lifecycle source of truth. Each carries the order, its status, the fired price and the settled entry price.

FillView
{
  fill: string; order: string;
  status: "armed" | "triggered" | "settled" | "cancelled";
  firedPrice: number; entryPrice: number; sig: number[];
}

watchFills(cb, intervalMs?)

Polls fills and invokes cb whenever a fill's status changes. Returns an unsubscribe function. Default interval 2500ms.

example
const stop = k.watchFills(f => {
  if (f.status === "settled") notify(`filled @ $${f.entryPrice}`);
});
// later
stop();

getOrder(order)

Reads and decodes one order by PDA — works even after it's been delegated into the rollup (raw fetch + decode), so you can inspect a live order's parameters.

cancel(order)

Cancels an order and commits the state back from the rollup. Returns the transaction signature.

quote(symbol, leverage, tradeType, inputAmountUi)

A live FlashTrade quote for the UI — the entry and liquidation prices a fill would get at the current mainnet price. Static helper; no wallet needed.

example
const q = await KestrelClient.quote("SOL", 5, "LONG");
// { entry: 75.04, liq: 67.61 }

Order types

Every order is a condition tree on the same crank — the types are presets over it.

kindFires when
stop_lossprice falls to/through the trigger
take_profitprice rises to/through the trigger
trailing_stopprice retraces trailOffset from the high-water mark
limit_buyprice reaches an entry level

On the roadmap, the same engine extends to multi-condition AND/OR, funding-rate and PnL/drawdown triggers, and brackets that attach FlashTrade-native exits on fire.

Architecture

Kestrel watches in one place and settles in another. An order is delegated into a MagicBlock ER (and, when private, a TEE) where the crank evaluates it gaslessly every tick. On a trigger, a post-commit Magic Action stamps the fill receipt on-chain; a keeper opens the position on FlashTrade and calls confirm_fill to anchor the execution.

In this build the watch loop runs on devnet (where the MagicBlock ER/TEE were developed) and FlashTrade settlement is on mainnet (where its liquidity lives), bridged by the keeper. In production Kestrel deploys on a mainnet ER and it collapses to a single cluster — the split is a development convenience, not part of the design.
